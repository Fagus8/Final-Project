## 📋 პროექტის შესახებ

**medical.ge** არის Next.js-სა და React-ზე დაფუძნებული ვებ-აპლიკაცია, რომელიც ექიმთან ვიზიტის დაჯავშნას სატელეფონო ზარებისა და რიგების გარეშე შესაძლებელს ხდის. პაციენტი პოულობს ექიმს, ხედავს მის თავისუფალ დროს და თავად ჯავშნის ვიზიტს, ვიზიტის შემდეგ კი თავის კაბინეტში ხედავს დიაგნოზსა და დანიშნულებას. ექიმი მართავს სამუშაო საათებსა და განრიგს, კლინიკა — თავის ექიმებს და ვიზიტებს, ადმინისტრატორი კი ამტკიცებს ახალ კლინიკებს. აპლიკაცია განკუთვნილია პაციენტებისთვის, ექიმებისთვის და კერძო კლინიკებისთვის.

| როლი | რა შეუძლია |
| :--- | :--- |
| **პაციენტი** | ექიმის ძებნა, ვიზიტის დაჯავშნა და გაუქმება, დიაგნოზებისა და დანიშნულებების ნახვა |
| **ექიმი** | კლინიკასთან შეერთება, სამუშაო საათების მართვა, დიაგნოზისა და დანიშნულების ჩაწერა |
| **კლინიკა** | ექიმების მოწვევა, დადასტურება და მართვა, ვიზიტების ნახვა |
| **ადმინისტრატორი** | ახალი კლინიკების დამტკიცება და რედაქტირება, პაციენტების სია |

## ✨ ძირითადი ფუნქციონალი

- **მონაცემთა მართვა (CRUD):** ვიზიტების, ექიმების, კლინიკებისა და პროფილების შექმნა, რედაქტირება და წაშლა ხდება REST API-ით (`src/app/api/`), მონაცემები ინახება PostgreSQL ბაზაში Prisma ORM-ის საშუალებით.
- **ავტორიზაცია და როლები:** რეგისტრაცია და შესვლა Better Auth-ით; თითოეული გვერდი და API მოთხოვნა ამოწმებს მომხმარებლის როლს (პაციენტი / ექიმი / კლინიკა / ადმინისტრატორი).
- **ჯავშნის ლოგიკა:** ექიმის სამუშაო საათებიდან და უკვე დაკავებული ვიზიტებიდან თავისუფალი დროის სლოტების გამოთვლა (`src/lib/availability.ts`), კალენდარი `dayjs`-ით; ორმაგი ჯავშნის დაცვა სერვერზე.
- **ფორმები და ვალიდაცია:** ფორმები `Formik`-ით, მონაცემების შემოწმება `Zod` სქემებით როგორც ბრაუზერში, ისე API-ში.
- **მოდალური ფანჯარა:** დიაგნოზის ჩაწერის ფორმა იხსნება HTML-ის ნატიური `<dialog>` ელემენტით (`showModal()`).
- **მდგრადობა:** ფორმის გაგზავნისას ღილაკი იბლოკება (Double-Click დაცვა), სერვერის შეცდომები ნაჩვენებია მომხმარებლისთვის გასაგები ტექსტით.
- **API დოკუმენტაცია:** ყველა API აღწერილია OpenAPI-ით და ხელმისაწვდომია `/docs` გვერდზე (Swagger UI, ჩაიტვირთება ზარმაცად `next/dynamic`-ით).
- **ტესტები:** დროის სლოტებისა და ჯავშნის API-ის ლოგიკა დაფარულია Vitest ტესტებით.
- **Responsive დიზაინი:** SCSS მოდულები, CSS Grid / Flexbox და `@media` წერტილები (480px – 1000px); მობილურზე გვერდითი მენიუ იკუმშება მხოლოდ აიქონებად.

## 📁 პროექტის სტრუქტურა

```text
prisma/
├── schema.prisma        # ბაზის სქემა (მოდელები და კავშირები)
├── migrations/          # ბაზის ცვლილებების ისტორია
└── seed.ts              # სადემონსტრაციო მონაცემები
src/
├── app/                 # გვერდები და API (Next.js App Router)
│   ├── (public)/        # ყველასთვის ღია: ექიმები, კლინიკები
│   ├── (auth)/          # შესვლა და რეგისტრაცია
│   ├── (account)/       # პირადი კაბინეტი (dashboard)
│   ├── (patient)/       # პაციენტის გვერდები: ჯავშანი, ვიზიტები, პროფილი
│   ├── (staff)/         # ექიმისა და კლინიკის გვერდები
│   ├── (admin)/         # ადმინისტრატორის გვერდები
│   ├── (docs)/          # Swagger API დოკუმენტაცია
│   └── api/             # REST API endpoint-ები
├── components/          # ხელახლა გამოყენებადი UI კომპონენტები
│   ├── appointments/    # ვიზიტის მოქმედებები (დიაგნოზის მოდალი, გაუქმება)
│   ├── clinics/         # კლინიკის კომპონენტები
│   ├── doctors/         # ექიმის პროფილისა და პარამეტრების ფორმები
│   ├── home/            # მთავარი გვერდის სექციები
│   ├── navigation/      # Header, Sidebar, ნავიგაციის ბმულები
│   └── ui/              # საბაზისო UI: Card, Calendar, Icon, Avatar
├── lib/                 # სერვერის ლოგიკა: ავტორიზაცია, ბაზა, დროის სლოტები, API დამხმარეები
├── styles/              # გლობალური სტილები, ფერები და საერთო mixin-ები
└── generated/           # Prisma-ს მიერ დაგენერირებული კლიენტი (ხელით არ იცვლება)
```

`src/app`-ში ფრჩხილებიანი საქაღალდეები, მაგალითად `(patient)` და `(staff)`, გვერდებს როლების მიხედვით აჯგუფებს. ეს სახელები მისამართში არ ჩანს: `src/app/(patient)/booking` გვერდის მისამართია `/booking`.

## ⚙️ ლოკალურად გაშვების ინსტრუქცია

საჭიროა **Node.js** (20+) და **PostgreSQL**.

1. **დააკლონირეთ რეპოზიტორია:**

   ```bash
   git clone https://github.com/Fagus8/Final-Project.git
   cd Final-Project
   ```

2. **დააყენეთ პაკეტები:**

   ```bash
   npm install
   ```

3. **შექმენით `.env` ფაილი** პროექტის ძირეულ საქაღალდეში:

   ```env
   DATABASE_URL="postgresql://USER:PASSWORD@localhost:5432/DATABASE"
   BETTER_AUTH_SECRET="ნებისმიერი გრძელი შემთხვევითი სტრიქონი"
   ```

   `.env` Git-ში არ იტვირთება, ამიტომ თითოეულ კომპიუტერზე ცალკე იქმნება.

4. **შექმენით ბაზის ცხრილები და სადემონსტრაციო მონაცემები:**

   ```bash
   npx prisma migrate dev
   npx prisma db seed
   ```

5. **გაუშვით დეველოპერული სერვერი:**

   ```bash
   npm run dev
   ```

   გახსენით ბრაუზერში: [http://localhost:3000](http://localhost:3000)
